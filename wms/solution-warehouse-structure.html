Gray's warehouse currently operates with Oracle Fusion ERP managing inventory at subinventory level only — locator control is not enabled. Inventory is tracked at the organisation → subinventory layer (e.g., DUTY_PAID), with no physical bin, shelf, or aisle assignment. As the WMS evolves to support guided picking, putaway rules, cycle counting, and route optimisation, a mechanism for tracking physical stock locations is required. Two architecture options exist — enabling Oracle Fusion locators, or maintaining a parallel locator database inside WMS. This document analyses both and recommends the lower-risk path.

4 · Option A — Enable Oracle Fusion Locators
A

Oracle Fusion Locator Control

Configure Fusion Inventory to enforce locator-level stock tracking. All transactions reference a physical bin.

HIGH RISK
Est. 6-8 months
What Needs to Be Done in Fusion
STEP 1 · DEFINE STRUCTURE
Define all physical locations in Fusion: Organisation → Subinventory → Zone → Locator (e.g., A-03-2-B). Set capacity, weight, dimensions per locator.
STEP 2 · ENABLE CONTROL
Enable Locator Control on the DUTY_PAID subinventory. Once enabled, ALL in/out transactions must reference a locator. No partial rollout.
STEP 3 · MIGRATE STOCK
Physically scan and map every item in the warehouse to a Fusion locator. All existing on-hand balances must be reassigned — this is a warehouse freeze event.

7 · Recommendation

Implement Option B Now — Evolve to Option A Later

The warehouse needs physical location tracking today. Enabling Oracle Fusion locators is a significant ERP project that requires extensive setup, a warehouse freeze for stock migration, and breaking changes to every transaction API — a 6-8 month commitment. Option B delivers the same operational benefit in 3-4 months with no risk to current Fusion transactions. The two systems can converge in a future phase once all physical locations are barcoded and the Fusion locator structure is fully defined.

Reason 1 · SpeedDeliver bin-level tracking 4 months faster. Pickers get location guidance in Q3 2026 rather than Q1 2027.
Reason 2 · Zero ERP RiskOracle Fusion transactions continue unchanged. No ERP change freeze, no UAT cycle, no regression testing on financial transactions.
Reason 3 · IncrementalRoll out one warehouse zone at a time. Learn and adjust before committing the entire warehouse.
Reason 4 · Future PathOption B data model is designed to map cleanly to Fusion locators. When Fusion locators are enabled in Phase 3, the WMS stock data migrates across.
8 · High-Level Implementation Plan (Option B)
1

Foundation — Location Data Model 4 weeks

Design and build the core location infrastructure in WMS and Oracle APEX.

  • Create wms_locations, wms_location_stock, wms_location_moves tables
  • Build Location Management screen in WMS (Zone → Aisle → Bay → Shelf → Bin)
  • Define location parameters: capacity, type (BULK/PICK/OVERFLOW), barcode
  • REST APIs: get locations, get stock by location, search by barcode
2

Putaway Integration — Receiving Flow 3 weeks

Update mobile receiving flow to record the physical putaway location in WMS.

  • WMS putaway suggestion engine (by item category, weight, zone rules)
  • Mobile app: show suggested locator → picker scans bin barcode → confirm
  • Fusion receiving API unchanged — subinventory only
  • WMS records: item + qty + locator + received_date
3

Guided Picking — Pick Task Enhancement 3 weeks

Update pick task generation to include WMS locator and optimise pick routes.

  • FIFO locator selection from wms_location_stock
  • Mobile app shows: "Go to A-03-2-B · Pick 3 units of ITEM-XYZ"
  • Picker scans locator barcode to confirm
  • WMS deducts stock; Fusion issues from subinventory on ship confirm
  • Basic route sorting (by aisle order)
4

Reconciliation & Reporting 2 weeks

Build the WMS vs Fusion stock comparison and cycle count framework.

  • Reconciliation report: WMS locator totals vs Fusion subinventory totals
  • Discrepancy alert and adjustment workflow
  • Cycle count task generation by zone/aisle
  • Location utilisation dashboard (% capacity used per zone)
5

Future — Migrate to Oracle Fusion Locators Phase 3 / TBD

Once warehouse is fully barcoded and Fusion locator structure is defined, migrate WMS locator data to Fusion and enable locator control. WMS becomes the UI layer; Fusion becomes the record of truth at locator level.
