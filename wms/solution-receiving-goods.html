1 · Executive Summary

Gray's WMS requires a structured inbound goods capability to replace the current manual receiving process. Three distinct flows are required: PO Receiving (goods arriving against a supplier purchase order), Duty Free / Bonded Receiving (same physical process directed to a bonded subinventory with additional customs fields), and Return Goods (customer returns, van returns, and store returns with an inspection and grading workflow). All three flows share a single Mobile Receiving App with flow-specific screens activated by receipt type.

FLOW 1 · PO RECEIVING
Goods received against a Fusion purchase order. Line-by-line scanning, lot/batch capture with expiry dates, inspection checklist, and guided putaway to a DUTY_PAID bin locator.
FLOW 2 · DUTY FREE RECEIVING
Identical mobile app to PO receiving. Subinventory switches to BONDED or DUTY_FREE. Extra customs fields captured (AWB, tariff code, customs declaration). Putaway restricted to bonded zone.
FLOW 3 · RETURN GOODS
Customer, van, and store returns. Each item inspected and graded A/B/C. Grade A back to saleable stock; Grade B to quarantine triage; Grade C to disposal and Fusion write-off.
Common Capabilities Across All Three Flows
Barcode scanning Lot/batch + expiry capture Guided locator putaway Inspection workflow Fusion ERP sync (subinventory level) FEFO lot selection at pick time

3 · PO Receiving
Overview

The PO Receiving flow fetches pending purchase orders from Oracle Fusion ERP and allows warehouse staff to receive goods line by line using a mobile device. Each received line captures the scanned item, quantity, lot/batch number, expiry date, and passes through an inspection step before the system suggests the optimal putaway locator. On completion the WMS calls the Fusion Inventory Receipt API to record the receipt at subinventory level, while WMS records the precise bin location and lot data independently.

PO List View
Supplier name, PO number, expected date, status badge (pending / partial / complete)
Scan & Qty
Camera barcode auto-identifies item. Partial and over-receipt detection with supervisor override flag
Lot / Batch
Multiple lots per PO line. Expiry date picker. FEFO applied at pick time using lot expiry
Inspection
Visual checklist, PASS/FAIL grade, damage notes field, optional photo capture
Putaway
System suggests 3 locators with capacity %, distance from dock, zone type. Scan bin to confirm
Fusion Sync
On confirm: Fusion receives at subinventory. WMS records lot + locator stock simultaneously

Lot / Batch Handling Detail
  • Each carton can carry a unique lot number and expiry date
  • Multiple lots per PO line are fully supported
  • FEFO applied at pick time — earliest expiry lot picked first
  • Quarantine flag on a lot suspends it from pick eligibility pending QA sign-off
  • Supplier lot reference stored alongside WMS internal lot number for full traceability

Locator Suggestion Algorithm

Evaluates available locators in priority order. Returns top 3 candidates for the receiver to choose from or scan directly.

  • 1
    Consolidation match — same item already stored in this locator. Reduces fragmentation and speeds future picking.
  • 2
    Category-zone match — item category maps to zone type (frozen items to cold storage, bulk to high-bay racking).
  • 3
    Sufficient remaining capacity — locator has enough weight/volume capacity for the quantity being put away.
  • 4
    Closest to receiving dock — minimise travel distance. Especially important for heavy or high-volume goods.
  • 5
    Preferred zone for item type — configurable preference rules per item master (e.g., fragile goods to lower shelves only).

Pros & Cons — PO Receiving
Pros
  • Real-time Fusion sync at point of receipt — stock available immediately
  • Full lot traceability from supplier batch to customer delivery
  • Guided putaway reduces mis-locations and improves space utilisation
  • Inspection at inbound catches supplier quality issues at the earliest point
  • FEFO lot selection at pick time significantly reduces expiry waste
  • Single app for all flows reduces training overhead
Cons
  • Mobile app development effort — 4+ weeks of build time for screens 1–7
  • Lot data entry adds time per carton vs bulk count-and-go receiving
  • Requires barcode infrastructure on all items and all locator labels
  • Fusion PO fetch API dependency — offline resilience design required
  • Over-receipt workflow requires supervisor escalation process definition
4 · Duty Free / Bonded Receiving
Overview

Duty Free / Bonded receiving uses the same mobile app and the same 7-screen flow as PO receiving. The key differences are: the target subinventory switches to BONDED or DUTY_FREE rather than DUTY_PAID; additional customs documentation fields are captured on the receipt header; and physical putaway is directed to the bonded zone, which is physically separated and access-controlled within the warehouse. Movement of bonded stock to duty-paid requires a separate customs clearance workflow which is out of scope for this phase.

Out of Scope for This Phase: The bonded-to-duty-paid movement (customs clearance workflow) will be designed in a separate solution document. This document covers inbound receipt to bonded stock only.

5 · Return Goods
Overview

Three return scenarios feed into a common inspection and grading workflow. All returns are captured via the mobile app, linked to the originating document where available (sales order, delivery trip, or store transfer), and each item is graded A, B, or C before any stock movement is made. Grade A items are returned to saleable stock at a locator in DUTY_PAID using the same locator suggestion engine as PO receiving. Grade B items go to a quarantine or triage locator for rework decision by the QA team. Grade C items trigger a disposal record and a Fusion inventory write-off. Customer returns additionally trigger a credit note process in Fusion.

Inspection & Grading — Three Outcomes
A
Resaleable
Passes full inspection. No visible damage. Packaging intact. Within expiry. Item is returned to saleable stock at a locator in DUTY_PAID subinventory using the same locator suggestion algorithm as PO receiving.
Putaway to stock · WMS location stock +qty
B
Minor Damage
Minor packaging damage or product condition concern. Not immediately resaleable without remediation. Directed to a designated triage area or quarantine locator. QA team makes the rework / repack / donate / dispose decision.
Quarantine locator · Rework decision pending
C
Unsaleable
Damaged beyond recovery, expired, or contaminated. Item directed to the disposal area. WMS creates a disposal record. Triggers a Fusion inventory write-off transaction. No stock is added back to any bin location.

Pros & Cons — Return Goods
Pros
  • Single app handles all three return types with minimal retraining
  • Grading at inbound prevents unsaleable stock re-entering active locations
  • Full audit trail linking return to originating order or delivery
  • Credit note trigger reduces manual finance steps for customer returns
  • Quarantine locator keeps Grade B items controlled and visible pending QA decision
Cons
  • Credit note API integration with Fusion requires mapping and testing
  • Grading decisions can be subjective — clear criteria and training required
  • Store returns may arrive in large batches requiring high-throughput scanning process
  • Disposal workflow requires waste management and write-off approval process to be defined
6 · API Design — Key REST Endpoints
Method Endpoint Description
GET /wms/v1/pending-pos Fetch pending purchase orders from Oracle Fusion. Returns PO header list with supplier, expected date, and status (pending / partial / complete).
GET /wms/v1/pos/{po_number}/lines Return all lines for a given PO — item number, description, ordered qty, received qty to date, lot-controlled flag.
POST /wms/v1/receipts Create a new receipt header. Body includes po_number, receipt_type (PO / DUTY_FREE), subinventory, and optional customs fields for duty free receipts (AWB, tariff code, customs value).
POST /wms/v1/receipts/{id}/lines Add a received line to an open receipt. Body: item_number, received_qty, lot_id, location_id, inspection_status, inspection_notes.
POST /wms/v1/receipts/{id}/confirm Confirm and close a receipt. Triggers the Fusion Inventory Receipt API at subinventory level. Updates WMS location stock and marks receipt as CONFIRMED.
GET /wms/v1/locators/suggest?item={item}&qty={qty}&subinv={subinv} Run the 5-rule locator suggestion algorithm. Returns top 3 locator candidates with capacity %, distance from receiving dock, and zone. For duty free: subinv=BONDED restricts results to bonded zone only.
POST /wms/v1/lots Create a new lot record. Body: lot_number, expiry_date, supplier_lot_ref, item_number, quarantine_flag. Returns lot_id for use in receipt lines.
POST /wms/v1/returns Create a return header. Body: return_type (CUSTOMER / VAN / STORE), linked_order_number, linked_delivery_id, notes.
POST /wms/v1/returns/{id}/lines Add a return line with inspection grade. Body: item_number, qty, lot_id, inspection_grade (A/B/C), location_id (Grade A only), inspection_notes, damage_description.
POST /wms/v1/returns/{id}/confirm Confirm and close a return. Triggers Fusion return receipt. Flags credit note required for customer returns. Updates WMS stock for Grade A items. Moves B/C items to quarantine / disposal.
7 · Implementation Plan — ~16 Weeks
1

Phase 1 — Foundation: Database & API Skeleton 3 weeks

Build the core data layer before any mobile screens. Establish patterns for all subsequent phases.

  • Create wms_receipts, wms_receipt_lines, wms_lots, wms_returns, wms_return_lines, wms_inspection_records in Oracle
  • Scaffold all REST endpoints in APEX ORDS (stub responses) — validate URL structure and authentication
  • Lot master CRUD APIs — create, search by item, filter by expiry window
  • Fusion PO fetch API integration — confirm response format, pagination, and auth headers
  • Define and document barcode format standards for items and locator labels
2

Phase 2 — PO Receiving Mobile App (Screens 1–7) 4 weeks

Build and integrate the full PO receiving mobile app flow with live API connections.

  • Screen 1: PO List — fetch from Fusion, filter by supplier / date / status
  • Screen 2: PO Detail — lines table with received vs ordered qty progress bars
  • Screen 3: Scan Screen — camera barcode, item auto-lookup, over/partial receipt logic and supervisor flag
  • Screen 4: Lot / Batch Entry — scan or type lot number, date picker for expiry, multi-lot per PO line
  • Screen 5: Inspection checklist — four checkboxes, PASS/FAIL toggle, damage notes, photo option
  • Screen 6: Putaway — locator suggestion API call, capacity bar display, scan locator barcode to confirm
  • Screen 7: Summary — review and submit, trigger Fusion receipt API on confirm, show sync status
3

Phase 3 — Lot Tracking & Locator Suggestion Engine 3 weeks

Implement the intelligence layer — FEFO lot selection at pick time and the 5-rule locator suggestion algorithm.

  • Locator suggestion engine — implement 5-rule priority algorithm with configurable zone weights
  • FEFO query: earliest expiry lot first for a given item when the pick task engine generates tasks
  • Quarantine flag logic: quarantined lots excluded from all pick suggestions automatically
  • Lot expiry dashboard — items expiring within 30 / 60 / 90 day windows
  • Lot traceability report — trace from supplier batch number to customer delivery
4

Phase 4 — Duty Free Receiving 2 weeks

Extend PO receiving flow with customs fields and bonded zone constraints. Mostly configuration with minimal new screens.

  • Add receipt_type flag and customs fields (AWB, tariff, origin, value, duty rate) to wms_receipts
  • Mobile Screen 1b: Customs fields form with AWB barcode scan support
  • Locator suggestion: filter to bonded zone locators only when receipt_type = DUTY_FREE
  • Fusion API: confirm correct subinventory code is passed (BONDED / DUTY_FREE)
  • Bonded stock report — current bonded inventory values pending customs clearance
5

Phase 5 — Return Goods (All 3 Types) 4 weeks

Build the full returns flow including inspection grading, quarantine management, and Fusion return receipt integration.

  • Return header creation — type selection (customer / van / store), link to order / delivery / store transfer
  • Item scan and lot lookup per return line with original delivery linkage
  • Grading workflow — A/B/C assignment with notes, photographic evidence capture
  • Grade A: trigger locator suggestion and confirm putaway to DUTY_PAID stock
  • Grade B: move to quarantine locator, create QA task for rework / repack / dispose decision
  • Grade C: disposal record creation, trigger Fusion inventory write-off API
  • Fusion return receipt API integration, credit note flag for customer returns
  • Returns dashboard: open returns by type, aged quarantine items, disposal cost tracking
~16 weeks
TOTAL ESTIMATED DELIVERY
Phases run mostly sequentially with some overlap between Phase 3 (lot engine) and Phase 4 (duty free, which is configuration-light). Phase 5 (returns) is the largest and requires Fusion return receipt and credit note API access to be confirmed before Phase 5 kicks off. Confirm this in Action 3 below.
8 · Next Steps & Open Actions
ACTION 1 · BARCODE INFRASTRUCTURE
Confirm Barcode Readiness
Determine whether all incoming items and supplier cartons carry readable barcodes. If not, define the labelling process for untagged goods on arrival. Confirm whether all warehouse locator positions have barcode labels printed and applied, or if a labelling programme needs to run first.
ACTION 2 · LOT NUMBER FORMAT
Define Lot Numbering Convention
Decide whether WMS adopts the supplier lot number as-is, generates an internal WMS lot number at receipt, or stores both with cross-reference. Define the format (e.g., WMS-LOT-YYYYMMDD-NNNNN). This decision affects all lot APIs, mobile screens, and traceability reports.
ACTION 3 · FUSION API ACCESS
Confirm Return Receipt & Credit Note API
Verify that the Oracle Fusion REST API for creating return receipts and triggering credit notes is accessible and licensed. Test a sample return payload in the Fusion sandbox environment before Phase 5 begins. Identify the Fusion service account with the correct inventory privileges.
