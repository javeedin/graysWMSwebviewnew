Solution Design — PO Receiving · Duty Free · Return Goods

A single Mobile Receiving Application handling three inbound flows — PO receipts, duty-free/bonded goods, and all return types — with barcode scanning, lot/batch expiry tracking, inspection grading, and guided locator putaway.

Gray's warehouse receives goods through three distinct channels, each requiring specific workflows: PO Receiving (supplier deliveries against purchase orders), Duty Free / Bonded Receiving (same process, different subinventory and additional customs fields), and Return Goods (customer returns, van returns, store returns with inspection grading). A single Mobile Receiving App handles all three, sharing core capabilities: barcode scanning, lot and batch number capture with expiry dates, quality inspection, and guided putaway to WMS-managed locators. Oracle Fusion continues to track inventory at the subinventory level only — consistent with the Warehouse Structure decision (Option B).

Lot / Batch Handling
  • 1Each physical carton can carry a unique lot number & expiry date
  • 2Multiple lots per PO line fully supported (add lot loop in screen 4)
  • 3Lot linked to locator — same lot can span multiple bins
  • 4FEFO (First Expiry First Out) applied at pick time using lot expiry date
  • 5Quarantine flag on lot — marks lot as on hold (QC fail, recall etc)
  • 6Expiry alerts: 30/60/90 day warnings in WMS dashboard
Locator Suggestion Algorithm
  • P1Same item already in locator — consolidate stock first
  • P2Match item category to zone (cold storage, flammable, pharma)
  • P3Sufficient remaining capacity (weight & volume headroom)
  • P4Closest locator to receiving dock (minimise travel)
  • P5User can override — scan any available locator barcode

  • Full lot traceability — scan → expiry → bin all linked
  • FEFO applied automatically at picking
  • Guided putaway reduces misplaced stock significantly
  • Real-time Fusion sync — subinventory updated on confirm
  • Inspection captures QC issues at point of receipt
Cons
  • Lot entry adds 1-2 min per unique lot — training needed
  • Requires all items to have scannable barcodes
  • Mobile app development effort: ~7 weeks
  • Barcode infrastructure investment (handheld scanners)
4 · Duty Free / Bonded Receiving

Duty Free / Bonded receiving uses the same Mobile Receiving App and the same 7-screen flow as PO Receiving. The user selects "Duty Free" as the receipt type on the PO List screen. Key differences are the target subinventory (BONDED), the physical zone for putaway (bonded area, physically separated), and additional customs fields that must be captured before submission.

Additional Customs Fields (Screen 2b)
IMPORT REFERENCE
AWB / Bill of Lading number. Mandatory before submission.
CUSTOMS DECLARATION
Customs authority declaration number (from clearance docs).
TARIFF CODE
HS Code. Used to calculate applicable duty rate.
COUNTRY OF ORIGIN
ISO country code for trade compliance and origin marking.
CUSTOMS VALUE (AED)
CIF value used for duty calculation. Stored on receipt line.
DUTY RATE %
Auto-populated from tariff code lookup. User can override.
Bonded → Duty-Paid Movement (Future Scope)
When goods are cleared through customs and duty is paid, a separate "Clearance Transfer" flow moves stock from the BONDED subinventory to DUTY_PAID in Fusion, and updates the WMS locator from the bonded zone to a duty-paid zone. This flow is out of scope for the current phase and will be designed separately.
5 · Return Goods
Three Return Types
🚚
Customer Return
Item returned after delivery — wrong item, damaged, excess order.
  • Trigger: Customer calls/emails, delivery team
  • Linked to: Original Sales Order
  • Inspection: Required — grade A/B/C
  • Credit: Fusion credit note triggered
🚐
Van Return
Driver returns undelivered items from failed deliveries at end of route.
  • Trigger: End of delivery route, driver check-in
  • Linked to: Trip / Delivery note
  • Inspection: Quick visual — was it already picked?
  • Credit: No — order status updated
🏪
Store Return
Retail store sends back slow-moving, near-expiry, or excess items.
  • Trigger: Store raises return request in WMS
  • Linked to: Store Transfer or sub-inventory
  • Inspection: Check expiry, resaleability
  • Credit: Store credit / inventory adjustment
Inspection Grading System
GRADE A
Resaleable
Packaging intact, item correct, no damage, expiry valid. Return directly to stock. Suggest free locator in DUTY_PAID zone.
Action: Put to stock → WMS locator
GRADE B
Minor Damage / Rework Needed
Packaging damaged, repackaging needed, near expiry but usable. Needs rework before resale. Move to triage area.
Action: Quarantine locator → QC review
GRADE C
Unsaleable
Damaged beyond repair, expired, contaminated, or wrong item with no resale value. Must be disposed of safely.
Action: Disposal → write-off in Fusion

6 · API Design
MethodEndpointDescription
GET/wms/v1/pending-posFetch pending POs from Oracle Fusion — supplier, date, status

GET/wms/v1/locators/suggestSuggest top 3 locators — params: item, qty, subinventory, weight_kg
POST/wms/v1/returnsCreate return header — type, source order ref, date
POST/wms/v1/returns/{id}/linesAdd return line — item, qty, grade (A/B/C), destination locator
POST/wms/v1/returns/{id}/confirmConfirm return — updates stock, triggers Fusion return receipt & credit
GET/wms/v1/items/{barcode}Identify item from barcode scan — returns item number, description, lot-controlled flag
